## Стек и ограничения (нельзя нарушать)
- Сайт: статические файлы на GitHub Pages (адрес вида theig01.github.io/ig_calendar/). Без сборки на моей стороне: всё, что нужно собрать, собираешь ты в своей песочнице.
- Бэкенд: один файл `worker.js` в Cloudflare Workers (бесплатно), KV-привязка `CAL`, секреты `BOT_TOKEN`, `PASSWORD`, опционально `WEBHOOK_SECRET`, cron каждую минуту. Telegram-бот через вебхук.
- Отчёты в Google Docs через Apps Script (`google-apps-script.gs`).
- Всё бесплатно, без платных API и без ключей в коде.
- Данные пользователя нельзя ломать: любые изменения структуры данных — только через миграцию (`S.v`), с автокопией перед миграцией.

## Жёсткие правила экономии лимитов
- Никогда не читай и не выводи в чат файлы целиком. Ищи `grep -n`, читай нужные диапазоны `sed -n 'a,bp'`. Код пиши прямо в файлы, в чат код НЕ вставляй.
- Правки делай точечно (замены, скрипты-патчи на Python/Node), а не перепечатыванием файла. Крупные механические преобразования (разрезание файла, форматирование, переименование) делай скриптом.
- Не повторяй аудит, не объясняй теорию, не делай «самопроверок» словами. Одна проверка перед выдачей: `node --check` для каждого изменённого .js (и скриптов в .html) + автотесты из `tests/`, если они есть. Скриншоты/браузер — только если без них не обойтись.
- Не трогай то, что не входит в задачу версии. Не меняй дизайн «заодно».
- Если задача явно не помещается в сессию: сделай первую законченную часть, пометь версию 🟨 в ROADMAP, остаток запиши в HANDOFF. Лучше маленький рабочий результат, чем большой незаконченный.
- Чекпоинты: как только готов первый рабочий блок — сразу собери архивы и положи в `/mnt/user-data/outputs/`, обнови HANDOFF. Потом дорабатывай и пересобирай. Так при обрыве лимита ничего не потеряется.

## Правила кода и качества
- Работающее не ломать. Перед правкой убедись, что понимаешь, где функция используется (`grep`).
- Читаемый код: функции небольшие, файлы короче 800 строк, понятные имена, комментарии только где неочевидно. Новый код — без inline `onclick` (делегирование через `data-act`), без `alert/prompt/confirm` (использовать общие окна/тосты, когда они появятся; до этого — аккуратные модальные окна).
- Любая новая функция: работает «из коробки» + имеет настройку в «Настройках» (вкл/выкл и параметры) + разумное значение по умолчанию + корректное пустое состояние.
- Доступность в новом UI: `aria-label` у иконок-кнопок, видимый фокус, управление с клавиатуры, контраст не ниже AA, крупные зоны нажатия на телефоне (≥44 px).
- Мобильная версия проверяется всегда: ширина 360–800 px.
- Все тексты интерфейса и бота — по-русски, простым тёплым языком.
- Версионирование: обнови `VERSION` в одном месте; строка версии видна в «Настройках → О сервисе»; имя кеша в `sw.js` и список файлов в SHELL обнови; добавь запись в `docs/CHANGELOG.md`.
- Дизайн: спокойный минимализм, мягкие тени, скругления 10–16 px, светлая тема по умолчанию (#f3f5f9 / карточки #fcfdff / текст #1a2133 / акцент #2f6bff), шрифты Manrope + Inter; расслабляющая атмосфера, умеренная мотивация (очки, серии, поздравления) — всё отключаемо.
- Данные: не меняй имена ключей хранилища и полей без миграции. Не добавляй зависимости, требующие платных сервисов.
